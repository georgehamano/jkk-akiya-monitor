## 2026-05-09

### 対応内容①：LINE通知が届かない問題の調査・解決

#### 症状
差分通知・日次レポートともに全く届かなくなった（2026-04-01以降）。

#### 原因
LINE Messaging API の**月間メッセージ上限（無料プラン：200通）**に達していた。
- GitHub Actionsのジョブはexit 0で終わるため「成功」に見えていた
- ログに `429 Client Error: Too Many Requests` が出力されていた

#### 解決
LINE Official Account のプランを**ライトプラン（5,000通/月 / ¥5,000）**にアップグレード。

#### 補足（2026-04-01の修正コミット漏れを同時に反映）
- `build_room_fingerprint` からsenpage除外（2通届くバグ修正）
- 日次cronを `30 22 * * *` → `15 23 * * *` に変更
- → これらは2026-04-01にローカルで修正済みだったが未コミットだったため、今回まとめて反映

### 対応内容②：地域フィルター通知機能の実装

#### 概要
LINEユーザーが区・市名を設定し、その地域の物件のみ通知を受け取れる機能。

#### user_prefs.json
`jkk-akiya-monitor` リポジトリに追加。
```json
{
  "Uxxxxxxxxxx": null,
  "Uyyyyyyyyyy": ["江戸川区", "葛飾区"]
}
```
- `null` = 全エリア（デフォルト）
- 配列 = 指定エリアのみ通知

#### LINE webhookエンドポイント（新規）
`jkk-akiya.com/api/line-webhook`（`src/app/api/line-webhook/route.ts`）

| ユーザー操作 | 処理 |
|------------|------|
| アカウントをフォロー | null で登録、ウェルカムメッセージ返信 |
| 「港区」など区・市名 | トグル追加/解除 |
| 「全エリア」「リセット」 | null に戻す |
| 「確認」 | 現在の設定を返信 |
| その他 | ヘルプを返信 |

GitHub API（PUT）で `user_prefs.json` を直接コミット更新。

#### 通知ロジックの変更（`jkk_line_notify.py`）

| 関数 | 役割 |
|------|------|
| `send_line_multicast()` | 最大500人に一括送信 |
| `send_line_push_to_one()` | 個別push |
| `notify_with_prefs()` | null→multicast、地域設定→push、空→broadcastフォールバック |
| `_build_daily_text()` | 地域絞り込み済みのレポートテキスト生成 |

日次レポートも地域フィルター対応（設定エリアの物件のみ表示）。

#### Vercel環境変数（追加）
- `LINE_CHANNEL_SECRET`
- `LINE_CHANNEL_ACCESS_TOKEN`
- `GITHUB_PREFS_PAT`（jkk-akiya-monitor への Contents: Write 権限）

#### LINE Developers設定
- Webhook URL: `https://jkk-akiya.com/api/line-webhook`
- 応答モード: Bot / Webhook ON / 自動応答メッセージ OFF

#### トラブルシューティング記録
- Vercel環境変数追加後は**再デプロイが必須**（既存デプロイには反映されない）
- LINE自動応答メッセージがwebhookより先に返信していた → LINE Official Account Managerで「応答メッセージ」をOFF
- `--test` 配信はbroadcastのため地域フィルターは効かない（設計通り）

## 2026-04-01

### 対応内容：LINE通知が2通届く不具合の修正

#### 症状
更新を検知したとき、LINE通知が2通届く。

#### 原因

**原因1：フィンガープリントにsenpageを含めていた**
`build_room_fingerprint` のシグネチャに senPage の4引数すべて（p1〜p4）を含めていたため、リクエストごとにサイト側で p1/p4 が変化した場合、同じ物件・同じ戸数でも「内訳変更（rotation）」として誤検知されていた。
- Loop 1：新規物件を「新規掲載」として通知・状態保存
- Loop 2（40秒後）：senpageが変化 → フィンガープリント差異 → 「内訳変更」で2通目の通知

**原因2：2つのcronスケジュールが22:30 UTCで重複**
`*/30 * * * *`（毎30分）と `30 22 * * *`（日次レポート）が22:30 UTCに同時発火し、GitHub Actionsが2ジョブを起動していた。

#### 修正内容

| ファイル | 変更箇所 | 変更内容 |
|----------|----------|----------|
| `jkk_line_notify.py` | `build_room_fingerprint`（1004行目付近） | シグネチャを `"{room}\|{count}"` に変更（senpage除外） |
| `.github/workflows/monitor.yml` | 日次cronスケジュール | `30 22 * * *` → `15 23 * * *`（23:15 UTC / 日本時間8:15）に変更 |
| `.github/workflows/monitor.yml` | `--daily` 判定条件 | `"30 22 * * *"` → `"15 23 * * *"` に合わせて修正 |
